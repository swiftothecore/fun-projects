# Additional bug audit — 7 November 2026

101 additional issues fixed across all 12 projects, the project directory, and cloud sync. The starting commit is `1ef9219`; the 104 issues in `BUGS.md` were already fixed there and are excluded from this audit.

Each numbered issue below maps to one regression in `tests/audit-regressions.cjs`. All 101 fail against an archive of the starting commit and pass against the repaired source. Related paths within one feature (such as all fields in a form or all card views) are grouped in one issue. Shared sync fixes count once, regardless of how many apps use them. `tests/audit-verification.json` records both outcomes for every issue.

## Verification

- New regressions: 101/101 pass; baseline: 0/101 pass.
- Existing cross-project regressions: 114/114 pass.
- Desktop/mobile smoke checks: all 26 page/viewport combinations pass, with no uncaught JavaScript errors, missing local assets, or horizontal overflow.
- Watchlist functional suite passes. Focused suites pass: bughunt 40/40, forms/API 11/11, imports 15/15, render/UI 11/11, storage 15/15.
- `node tests/check-scripts.cjs`: 40 scripts parse. `git diff --check` passes.
- Inspected desktop and mobile renders of the changed directory, album menu, music controls, palette gallery, and TV/film forms.

Browser tests use isolated profiles, fixture storage, and intercepted external requests. No live API/cloud accounts or personal browser data are used. The optional real Supabase SDK checks remain skipped. Native Safari and live service behavior are not covered.

## Compatibility

Library storage keys and cloud tables remain unchanged. Pending-sync markers now use `_sb_pending_<table>` so app saves cannot mark another app as dirty. A legacy `_sb_pending` marker is claimed once by the next connected app, then removed. The old global marker does not identify which app created it, so the migration preserves it for that first app. Existing regression assertions follow the scoped key; their legacy seed fixtures still test migration.

New palette records store their flipped orientation. Older records without this optional field use the original unflipped default. Valid records beside malformed local TV/film records are retained. Cloud payload validation remains atomic.

```sh
# Use an installed Playwright package and Chromium-compatible browser.
export PLAYWRIGHT_PATH=/absolute/path/to/playwright
export BROWSER_PATH=/absolute/path/to/browser
export WATCHLIST_PLAYWRIGHT_PATH="$PLAYWRIGHT_PATH"
node tests/audit-regressions.cjs
node tests/bug-regressions.cjs
node tests/smoke.cjs
node tests/check-scripts.cjs
WATCHLIST_SKIP_VISUAL=1 node my-watchlist/tests/regression.cjs
node my-watchlist/tests/bughunt.cjs
node my-watchlist/tests/forms-api-bugs.cjs
node my-watchlist/tests/imports-bugs.cjs
node my-watchlist/tests/render-ui-bugs.cjs
node my-watchlist/tests/storage-bugs.cjs

# Reproduce the new failures in a separate baseline directory:
mkdir -p /tmp/fun-projects-audit-baseline
# Use a fresh directory if that path already contains files.
git archive 1ef9219 | tar -x -C /tmp/fun-projects-audit-baseline
FUN_PROJECTS_ROOT=/tmp/fun-projects-audit-baseline node tests/audit-regressions.cjs
```

`CASES=1,2,3` selects individual new regressions. `RESULTS_FILE=/path/to/results.json` writes their outcomes. A regression command exits nonzero on failure, so the baseline run is expected to exit nonzero.
